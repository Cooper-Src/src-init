# Manifest Format

This document defines the `.src` manifest format used by the **src** package manager.

Every package available through a `src` registry is represented by exactly one manifest.

---

# Overview

A manifest contains metadata describing a source package.

Example:

```ini
name = raylib
version = 6.0
description = A simple and easy-to-use library to enjoy videogames programming

[source]
type = archive
url = https://github.com/raysan5/raylib/archive/refs/tags/6.0.zip
format = zip

[license]
name = Zlib

[homepage]
url = https://www.raylib.com
```

---

# File Extension

All manifests use the extension

```
.src
```

Example

```
raylib.src
```

---

# Encoding

Manifest files must be encoded as

```
UTF-8
```

without a Byte Order Mark (BOM).

---

# Root Fields

## name

The package name.

```ini
name = raylib
```

Requirements

- Required
- Unique within a registry
- Case-sensitive
- Should match the upstream project name

---

## version

The upstream package version.

```ini
version = 6.0
```

Examples

```
6.0
v1.3.1
2026.04
```

Requirements

- Required

---

## description

A short human-readable package description.

```ini
description = A simple and easy-to-use library
```

Requirements

- Required
- Single line
- Keep concise

---

# Source Section

```
[source]
```

Defines where the package source can be downloaded.

---

## type

The package source type.

```ini
type = archive
```

Currently supported

| Type | Description |
|------|-------------|
| archive | Download a compressed source archive |

Future versions may support additional source types.

---

## url

The download URL.

```ini
url = https://github.com/raysan5/raylib/archive/refs/tags/6.0.zip
```

Requirements

- Required
- HTTPS recommended
- Must point to a downloadable archive

---

## format

Archive format.

```ini
format = zip
```

Supported formats

| Format |
|---------|
| zip |

Future versions may support

```
tar.gz
tar.xz
7z
```

# Validation Rules

A valid manifest must

- contain every required field
- contain exactly one `[source]` section
- contain exactly one `[license]` section
- contain exactly one `[homepage]` section
- use UTF-8 encoding
- use Unix or Windows line endings
- use valid URLs

---

# Best Practices

## Package Name

Use the upstream project name.

Good

```ini
name = raylib
```

Avoid

```ini
name = raylib-library
```

unless required.

---

## Version

Use the upstream version exactly.

Good

```
6.0
v1.4.2
```

Avoid

```
latest
stable
master
```

---

## Description

Keep descriptions concise.

Good

```
A modern formatting library for C++.
```

Avoid

```
This library was originally created...
```

---

## License

Use SPDX identifiers whenever possible.

Good

```
MIT
Apache-2.0
BSD-3-Clause
```

---

# Future Extensions

The manifest format is intentionally extensible.

Future versions may introduce sections such as

```ini
[dependencies]
```

```ini
build = cmake
```

```ini
[authors]
```

```ini
[documentation]
```

while remaining backward compatible with existing manifests.

---

# Compatibility

Current manifest version

```
Version 1
```

All manifests generated by `src-init` are compatible with Version 1 of the src registry format.

Future registry versions will maintain backward compatibility whenever practical.
